## Run contract for the watchlist skill

This block supplements the existing watchlist skill without changing its symbols, scoring formulas, or rating rules. Place it before the run order. The watchlist stays in the user's existing skill, rather than being duplicated in application code.

### Mandatory completion contract

1. Read the exact unique symbols in Section 10. Preserve share classes, exchange suffixes and hyphens. Use GOOG, not GOOGL. Do not substitute, silently remove, or add symbols. An inactive, gated or stale symbol still belongs to the coverage denominator. Reference benchmarks explicitly named by the skill may appear in the regime section, but may not become extra rated watchlist entries. Filter bulk news, calendar and insider feeds to the exact watchlist before writing ticker sections.
2. Establish the most recent completed session using the exchange calendar. A closed market means use that completed session; it does not mean omit daily prices. Split Phase C into C1 and C2. **C1:** use historical-price-eod-light with only the last 7 calendar days for EVERY exact Section 10 symbol, in batches of up to 20 independent tool calls. Build a compact price/date/volume ledger before fetching any ticker's long history or optional analyst/news/fundamental/flow data. After all symbols are attempted, audit fresh coverage; if it is below 90%, stop with the incomplete coverage report rather than spending the remaining budget on optional depth. **C2:** only after C1 passes, fetch the required 400-day adjusted history and compute technicals. Both phases are required for a complete report. If adjusted history is gated, light data may establish a price only; never invent OHLC, ATR, ADX or adjusted returns from close-only data. Respect the known Starter endpoint exclusions.
3. Checkpoint after each batch using memory_write and workspace_write. Maintain watchlist_state_YYYY-MM-DD.json with one record per exact symbol: status (fresh, stale, unavailable, not_attempted), session_date, price, currency, source tool/note id, failure reason where applicable, and available computed metrics with their as_of dates. Also save a compact coverage note listing total, attempted, fresh, stale, unavailable and not_attempted counts plus the exact missing symbols. Read previous state with workspace_list/workspace_read and follow next_offset through all pages. Never treat a truncated excerpt or an earlier narrative as the complete state.
4. Completion audit before any report: fresh price coverage = fresh / ALL unique Section 10 symbols. If fewer than 90% have verified prices for the expected completed session (125 of 138 for the current list), OR any symbol was never attempted, OR mandatory regime/technicals/scoring inputs or the required state artifact are missing, begin with **RUN INCOMPLETE**. Give the counts, exact missing symbols, reason, saved artifact path and unfinished phases. In an incomplete run, provide a factual coverage/data-quality report only: NO action ratings, composite rankings, Buy List, trade plans, or recommendation language. Do not disguise a limited analyst/news sample as the daily report. Never shrink the denominator to make the gate pass.
5. Passing price coverage alone does not authorize a rating. Apply Sections 4-7 exactly. Every implied upside needs a verified price and target from the matching exact symbol, compatible currency and stated dates: (target / price - 1) x 100. Falling target revisions disable the upside contribution. Missing prerequisites mean n/a and block the affected rating; optimistic adjectives cannot replace the rules. Only computed metrics from actual data may support regime labels, scores and technical claims. If the available tools cannot perform a required computation, disclose it as unfinished rather than fabricating the result.
6. Use 10Y level/change, SPY trend and watchlist breadth for the regime, as defined in Section 6. Equity risk premium or unrelated foreign calendar items cannot substitute for those inputs. Apply the existing materiality filter before reporting news; discard materiality-0 items. Preserve the existing Buy List freshness, earnings, restricted-ticker and risk/reward gates.
7. Follow the report order in Section 8 only after the completion audit passes. Finish the requested report without asking the user which already-defined phase to do next. If execution is forced to end by budget, time or context capacity before the audit passes, use the incomplete format above. Do not claim that missing evidence was never fetched: consult the handed-off state and authored task notes, and distinguish unavailable data from omitted context.
