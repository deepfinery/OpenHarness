# Operating an installation

## Storage and services

The default Compose project is `agentic-orchestration`. It owns four volumes:
Mongo metadata, RabbitMQ state, Weaviate vectors, and uploaded files. All storage
belongs to this installation. Service credentials are randomly generated by
`start.sh`; database and broker ports are not published.

```sh
docker compose ps
docker compose logs --tail=100 api runner
docker compose stop
docker compose up -d --wait
```

`docker compose down` preserves volumes. `docker compose down -v` deletes the
installation's stored data and should only be used for an intentional reset.

Back up `.env` securely and snapshot all four volumes together with the API and
runner stopped. For a filesystem/storage snapshot service, quiesce database
writes and capture the corresponding MongoDB and Weaviate data as a consistent
set. Restore using matching service versions before attempting upgrades.

`ENCRYPTION_KEY` must be restored with MongoDB. Rotating it without decrypting
and re-encrypting existing credentials makes those credentials unreadable.
Changing database/broker credentials in `.env` does not rotate credentials
already persisted inside their volumes: follow the relevant service's account
rotation procedure as well.

## Shared filesystems and scaling

For a host-mounted filesystem:

```sh
mkdir -p /mnt/agentic
FILES_PATH=/mnt/agentic docker compose \
  -f compose.yaml -f compose.shared-fs.yaml up --build -d --wait
```

For NFS or another shared mount, arrange for UID 1000 to own or be able to write
the directory. The storage initializer creates `/data/files`; root-squashed NFS
may require creating/owning that directory on the server first. All API and
runner replicas must see the same files. Metadata and vectors live in MongoDB
and Weaviate, not in the uploaded-files directory.

```sh
docker compose up -d --scale runner=2
```

Each runner consumes `WORKER_CONCURRENCY` jobs (default 2). Use provider quotas,
available memory and workload duration to choose concurrency. The default
single Mongo, RabbitMQ and Weaviate services are a laptop/server deployment,
not a high-availability cluster. Configure replicated deployments separately
if infrastructure failover is required.

## Network and TLS

The studio binds to `127.0.0.1:8088` by default. Put a reverse proxy with TLS in
front of it on a server. Set `PUBLIC_URL=https://agents.example.com`, configure
the proxy, and recreate the application containers. HTTPS enables Secure
session cookies. Set `TRUST_PROXY` to the exact number of trusted proxy hops;
leave it at zero for direct connections.

Use `STUDIO_BIND=0.0.0.0` only when intentionally exposing the HTTP listener to
your network or a separately isolated proxy. Keep MongoDB, RabbitMQ, Weaviate
and the shared filesystem private. The API's `/api/health` endpoint checks its
database, broker, and vector store. Compose also checks the runner heartbeat.

For local MCP or model servers, set `ALLOWED_PRIVATE_HOSTS` to their exact
hostnames. The default host gateway is `host.docker.internal`. The Ollama host
service must be listening on an interface reachable from Docker. Do not use
`localhost` inside a container to refer to the laptop's host.

## Jobs and recovery

- Broker outage: new submissions remain in MongoDB. The dispatcher republishes
  queued work when the broker returns.
- Runner outage: RabbitMQ redelivers unacknowledged work, but the persisted run
  lease prevents replay. After lease expiration the run becomes `interrupted`.
- Indexer outage: expired indexing leases return to the queue. Deterministic
  vector IDs and replacement of partial vectors allow reindexing.
- A malformed queue message goes to `agentic.jobs.dead`. Normal agent/model
  failures are recorded on the run and acknowledged.
- Cancellation is cooperative and polled at five-second intervals. MCP and model
  requests receive abort signals. Remote services may already have acted.
- A schedule that cannot submit a run records its error in the workflow's
  scheduled-run settings and retries after one minute. Other schedules continue.

Review an interrupted run's trace before submitting a new run. Node checkpoints
are for inspection, not an assertion that an external action is safe to replay.

## Release checks

The checked-in CI builds the project and runs tests against an isolated stack.
It exercises authentication/isolation, protocol adapters, MCP HTTP and SSE,
OAuth state/PKCE/refresh, Weaviate retrieval, API/embed permissions, cancellation,
broker recovery, worker interruption, schedules and browser workflows.

The deterministic model and MCP fixtures are only loaded by the test Compose
overlay. Live provider behavior, model quality, tool side-effect policies, large
document parsing, sustained-load behavior and a specific server's OAuth
implementation still need deployment-specific validation.
